================================================================================
CRITICAL RISKS FOR PRODUCTION
================================================================================

RISK #1: SILENT FAILURES IN RECURSION (Severity: HIGH)
  - Both left/right recursive branches can fail
  - Current code handles this but NOT TESTED
  - Production may encounter untested failure scenarios
  - Impact: Queries fail silently instead of returning error

RISK #2: RACE CONDITIONS IN CONCURRENT USAGE (Severity: HIGH)
  - Chunk IDs generated as f"chunk_{len(chunks)}"
  - If two chunking operations run simultaneously, ID collisions possible
  - No synchronization primitive for chunk ID generation
  - Impact: Chunks could be lost or overwritten

RISK #3: MALFORMED CHUNKS NOT VALIDATED (Severity: MEDIUM)
  - Empty chunks can pass through chunking strategy
  - No validation before sending to LLM
  - Wastes tokens on meaningless queries
  - Impact: Wasted API calls and budget

RISK #4: TOKEN BUDGET EDGE CASES (Severity: MEDIUM)
  - Zero token budget not tested
  - Negative token counts not validated
  - Budget exhaustion mid-compilation not covered
  - Impact: Unexpected behavior or crashes

RISK #5: SENTENCE SPLITTING FRAGILITY (Severity: LOW)
  - Simple regex-based splitting fails on:
    * Ellipsis (...)
    * Abbreviations (Dr., Mr., etc)
    * URLs/emails (example.com)
    * Quoted content ("text. More.")
  - Impact: Bad chunks, reduced accuracy
